每个实验回答一个具体问题：这次验证了什么、证据是什么、下一步怎么做。程序跑通不等于产品有用，这里记录的是在真实条件下实际发生了什么。

## 怎么记录

每个实验一个文件，按编号命名（`001-名称.md`）。

开始前写好：目标、输入、步骤、要记录什么、通过标准。
结束后补上：实际结果（包括失败、误报、漏报、延迟和人工判断）、结论和下一步。

- 预期和实际分开写，跑完后不回头改预期或通过标准。
- 结论只覆盖这一次的条件（哪个平台、什么商品、什么设备），不从一场推断所有场景。
- 记下程序版本（`git rev-parse --short HEAD`），以后才能对得上是哪一版的结果。

## 隐私

仓库是公开的，这里只放计划、统计数字和结论。

- **不写进仓库**：直播间名称和链接、主播或观众的信息、录音、完整转写、复盘报告原件、截图。
- **留在本机**：录音在程序数据目录的 `recordings` 文件夹；导出的复盘报告、核对表的原始版本放在 `.local/experiments/<编号>/`（`.local/` 已被 git 忽略）。
- 实验记录里引用原话时，只摘与结论有关的几个字，不贴整段讲解。
